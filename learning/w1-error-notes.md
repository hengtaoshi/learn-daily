# W1 报错笔记合集（踩坑档案）

> 学习日期：2026-08-07 ｜ 规划硬规则：每次报错记「报错信息 + 原因 + 解法」
> 配套：第一课「终端基础」+ 第二课「find」

---

## 坑 1：全角波浪号 `～` vs 半角 `~`

**报错信息：**
```bash
$ cd ～&&pwd
bash: cd: ～: 没有那个文件或目录
```

**原因：** 波浪号打成了**全角** `～`（中文输入法输出，占两个字符宽），命令只认**半角** `~`（英文键盘，占一个字符宽）。bash 把它当成一个叫"～"的文件去找。

**解法：** 终端里的所有符号（波浪号、引号、括号、连字符）必须用**英文（半角）输入法**敲。切输入法后再敲 `cd ~`。

**防再犯：** 看到 `bash: cd: xxx: 没有那个文件或目录`，先检查是不是全角符号；敲命令前确认输入法是英文。

## 坑 2：find 的「空格三连错」

**报错信息（三次尝试）：**
```bash
$ find /+100M
find: ‘/+100M’: 没有那个文件或目录

$ find / -size+100M
find: 未知的谓词 "-size+100M"

$ find / -size + 100M
find: 无效的 -size 类型 "+"
```

**原因：** 同一个病根——**bash 按空格把命令切成一个个词，空格的位置就是命令的语法**。
- 第一次：把 `-size` 整个丢了（`/+100M` 被当成路径）
- 第二次：`-size` 和它的值 `+100M` 之间**少一个空格**，粘成了不认识的词 `-size+100M`
- 第三次：值 `+100M` 被**多一个空格拆开**，`+` 单独出现 bash 理解不了

**解法：** 命令的每个"部分"之间用一个空格隔开；但**属于同一个部分的字符之间不能有空格**（`+100M`、`*.log`、`-name` 都是整体）。

```bash
find / -size +100M    ✅ 空格在"部分之间"
```

**防再犯：** 敲命令时心里默念「部分之间空格、整体不拆」；`-选项` 和它的值永远是两个词。

## 坑 3：`~` 跟随身份变化

**现象：** root 身份下 `find ~ -type d -name "*learn*"` 结果为空，但 `find /home/hengtao ...` 有一堆结果。

**原因：** `~` 的意思是「**当前用户**的家目录」。`root` 的 `~` 是 `/root`，普通用户 `hengtao` 的 `~` 才是 `/home/hengtao`。**身份变了，`~` 跟着变。**

**解法：** 找文件时如果结果莫名为空，先用 `pwd`/提示符确认当前身份（`root@` 还是 `hengtao@`），必要时写全路径 `/home/xxx`。

**防再犯：** 看到提示符 `root@主机名` 就知道自己是 root，`~` 指向 /root。

---

## 坑 4：粘贴命令时带上多余字符

**现象：** 命令尾部粘上了 `4`（`2>/dev/null4`），find 报「未知的谓词」。

**原因：** 复制粘贴时多带了一个字符，命令被悄悄改坏。

**解法：** 粘贴长命令后，**先看一眼命令完整再回车**；报错时先检查命令本身有没有多余字符。

## 总结：报错不可怕，可怕的是不记

这次 4 个坑全是"看起来很小、实际很典型"的坑。**每次报错 = 一次免费的排查训练**，按「报错信息 + 原因 + 解法 + 防再犯」四段式记下来，攒成自己的排障素材库——这也是以后面试讲排障案例的现成弹药。
