# Linux 目录结构详解（实施岗版）

> 学习日期：2026-08-07 ｜ 配套：第一课「终端基础」（目录树概念）
> 定位：实施/交付岗需要掌握的目录地图——排障时知道"该去哪找"，比背命令更重要。

## 一、先建立整体图：Linux 的目录树

Linux 所有东西都是文件，所有文件挂在一棵树上，树根是 `/`（根目录）。整棵树的骨架：

```
/                       ← 根目录（树的根）
├── /etc                配置目录（天天碰）
├── /var                动态数据：日志、缓存、队列（天天碰）
│   └── /var/log        系统日志（排障核心）
├── /home               普通用户的家（天天碰）
├── /opt                第三方商业软件（实施常碰）
├── /root               管理员（root）的家
├── /tmp                临时文件
├── /usr                系统软件（软件的大本营）
├── /bin /sbin          命令程序
├── /lib /lib64         程序运行依赖的库
├── /run                系统运行时的临时状态
├── /proc /sys /dev     内核/硬件虚拟出来的"假目录"
├── /boot               开机启动文件
├── /mnt /media         手动挂载点 / 可移动设备
└── /lost+found         磁盘异常时找回文件的地方
```

> 判断标准：**实施岗天天碰的是前 6 个（重点学），后面的是排障会遇到（知道去哪即可）。** 这也是 W2 微调原则——运维只学够用的。

## 二、第一梯队：实施岗天天碰的目录（重点）

### 1. `/etc` —— 配置目录（最重要）

- **作用**：系统和服务**所有配置文件**的家
- **实施场景**：Nginx 配置在 `/etc/nginx/nginx.conf`、MySQL 在 `/etc/mysql/`、systemd 服务在 `/etc/systemd/system/`。**"服务行为不对"第一个要查的就是这里**
- **排障要点**：改配置前先 `cp xxx xxx.bak` 备份；`ls -l` 检查权限属主，权限不对服务拒绝读取
- 关联命令：`ls -l /etc`、`cat /etc/xxx.conf`

### 2. `/var/log` —— 日志目录（排障核心）

- **作用**：系统和服务的日志文件
- **实施场景**：服务起不来、报错排查，第一件事 `tail -f /var/log/xxx.log` 看实时日志
- **常见日志**：
  - `syslog` / `messages` — 系统总日志
  - `kern.log` — 内核日志（硬件、驱动问题看它）
  - `auth.log` — 登录认证日志（安全排查看它）
  - `dpkg.log` / `yum.log` — 包管理安装记录
  - 各服务的专属日志，如 `nginx/`、`mysql/` 子目录
- 关联命令：`ls -l /var/log`、`tail -f`、`journalctl`（W3 学）

### 3. `/home` —— 普通用户的家目录

- **作用**：每个普通用户一个子目录，如 `/home/hengtao`，存放个人文件、配置、项目
- **实施场景**：部署的脚本、备份、个人工具一般都放这里；`~` 就是 `/home/你的用户名` 的缩写（第一课学过）
- 注意：**普通用户没有权限写系统目录（/etc、/var 等）**，自己的东西都放 `~`

### 4. `/opt` —— 第三方软件目录

- **作用**：存放**可选（optional）的第三方软件**，通常是商业软件或手动安装的大软件，一个软件一个子目录
- **实施场景**：JDK、中间件、商业应用装这里是常见惯例；部署时确认"这个软件装哪"——`/opt` 和 `/usr/local` 是两大惯例位置
- 关联命令：`ls /opt`

### 5. `/root` —— root 管理员的家

- **作用**：超级管理员（root）的家，普通用户进不去
- **实施场景**：root 的脚本、密钥、备份放这；`su` 或 `sudo -i` 进去后默认就在这
- 注意：**能用 sudo 就少用 root**，这是安全习惯

### 6. `/tmp` —— 临时文件

- **作用**：所有用户都能写的临时目录，系统重启或定期清理会清空
- **实施场景**：临时下载、临时解压、测试文件都扔这；**重要东西千万别放 /tmp**，会被清掉

### 7. `/usr` —— 系统软件大本营

- **作用**：`/usr/bin` 放大部分命令、`/usr/local` 放手动编译安装的软件（如源码装的 Python）、`/usr/share` 放共享数据
- **实施场景**：`which python` 看命令在哪，经常指向 `/usr/bin/` 或 `/usr/local/bin/`
- 关联命令：`which 命令名`

## 三、第二梯队：排障会遇到（知道是干嘛的即可）

| 目录 | 作用 | 什么时候碰到 |
|---|---|---|
| `/bin` `/sbin` | 系统基本命令 / 管理员命令 | 命令不在 PATH 时排查 |
| `/lib` `/lib64` | 程序运行依赖的共享库 | 报"找不到 so 文件"时排查 |
| `/run` | 系统运行时的临时状态（PID、socket） | 看服务 PID 文件时 |
| `/proc` | **虚拟目录**，内核运行状态（CPU、内存、进程） | 看系统状态时；`cat /proc/meminfo` 等 |
| `/sys` | 虚拟目录，内核硬件设备信息 | 硬件/驱动排查 |
| `/dev` | 设备文件（硬盘、终端、USB） | 挂载磁盘时，如 `/dev/sda` |
| `/boot` | 开机启动文件（内核、grub） | 开机引导修复 |
| `/mnt` | 手动挂载点 | 手动挂盘时 `mount /dev/sdb /mnt/data` |
| `/media` | 可移动设备自动挂载（U 盘、光驱） | 插 U 盘时 |
| `/lost+found` | 磁盘异常/断电后找回的碎片文件 | 很少碰 |
| `/srv` | 服务提供的数据（网站文件等） | 有的部署规范用 |

> 记住一句话：**`/proc`、`/sys`、`/dev` 不是真的文件，是内核"假装"成文件的窗口**，让你可以用 `cat`、`ls` 的方式看系统状态——这是 Linux "一切皆文件"哲学的体现。

## 四、实施场景串联：三个真实场景怎么用目录

**场景 1：服务起不来**
`cd /var/log` → `tail -f 服务日志` 看报错 → `cd /etc` → `ls -l` 检查配置权限 → 改配置（先备份）→ 重启

**场景 2：磁盘满了（告警）**
`df -h` 看哪个分区满 → `find / -size +100M 2>/dev/null` 找大文件 → 清理 `/tmp`、日志或备份

**场景 3：新装的软件找不到**
`which 软件名` 看命令路径 → 检查是否在 `/usr/local/bin`（源码装）还是 `/opt`（第三方装）→ 加 PATH

## 五、快速记忆表（贴在电脑前）

| 目的 | 去哪找 |
|---|---|
| 配置文件 | `/etc` |
| 日志 | `/var/log` |
| 我的文件 | `/home/用户名`（`~`） |
| 第三方软件 | `/opt` |
| 临时文件 | `/tmp` |
| 命令在哪 | `/usr/bin`、`/usr/local/bin` |
| 磁盘/设备 | `/dev`、`/mnt` |

一句话总结：**实施排障 = 脑子里有一张目录地图，知道"什么类型的东西放在哪"，90% 的问题都能少走一半弯路。**
